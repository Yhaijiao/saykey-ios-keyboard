## 1. 目标和取舍

- 这是一次**学习型项目**：完整走一遍「个人开发 → 小规模美国商业化」的流程，学会后做别的产品。实用价值次要（国内有豆包；SayKey 的意义是私密语音输入）。
- **隐私第一**：不用中国托管的识别；音频只发到用户自己的服务器，处理完即删。
- **能发出去比打磨重要**；照顾 Jeremy 的额度和时间。
- 商业化设想：自己的网站 → App Store，免费 + 付费，收入覆盖服务器成本；宣传「音频处理完即删除」；可选自带服务器。Jeremy 说过：**能接上亚马逊公有云（AWS）之后，SayKey 就进入商业化阶段**。上架前要先核查模型和组件的许可证。
- App Store 最终名字未定（他喜欢 TypeSay / TexSay），上架时再查重名和商标；到时只改显示名，不改 Bundle ID。

## 3. 安装（SideStore）

- iPhone 用 SideStore 侧载，免费 Apple ID 签名，7 天续签。
- **SideStore 安装/更新时弹出选项，永远选第 2 项「Keep App Extensions (Register App ID for Each Extension)」**，因为键盘扩展需要自己的 App ID / App Group。
- 以后更新：主 App →「更新与续签」→「用 SideStore 安装更新」。Jeremy 不接受 USB 安装或丢失一键更新。
- 手机只在安装时用 LocalDevVPN，平时用 Tailscale 连家里电脑。

## 4. 编译和发布（一步一步）

iOS 只能在 macOS 上编译，所以都在 GitHub Actions 上做。详见 [RELEASE.zh-CN.md](RELEASE.zh-CN.md)。

**编译**
1. 打开仓库 Actions → **Build iPhone keyboard for sideloading** → Run workflow → 选你的分支 → Run。
   - 命令行（如果电脑装了 GitHub CLI `gh`）：`gh workflow run build-ios.yml --repo Yhaijiao/saykey-ios-keyboard --ref <分支名>`
   - 要跑模拟器界面测试就勾选 `simulator_tests`（命令行加 `-f simulator_tests=true`）。默认不跑，省 Mac 时间。
2. PR 不会自动触发编译，要手动跑。只编译约 3 分钟 Mac 时间。
3. 记下这次运行的编号（网址里 `/actions/runs/` 后面那串数字）。

**发布**（PR 合并进 `feature/phone-asr`、一批功能都做完以后）
1. 在 `feature/phone-asr` 上编译一次并确认成功。
2. 同一个 workflow 再 Run 一次，在「只发布」一栏（`publish_run_id`）填上一步的运行编号。
   - 命令行：`gh workflow run build-ios.yml --repo Yhaijiao/saykey-ios-keyboard --ref feature/phone-asr -f publish_run_id=<编号>`
3. 它会校验 SHA-256，把 IPA 以 `CapsWriterLab-sideload.ipa` 的名字传到 `saykey-releases` 的 `lab-phone-asr`，同时尝试刷新代码仓库里的旧下载（失败不影响）。
4. 告诉 Jeremy 版本号，他在手机上点更新。

**发布需要的密钥**：仓库 Settings → Secrets and variables → Actions 里的 `RELEASES_TOKEN`（只授权写 `saykey-releases` 的 fine-grained 令牌，不过期）。报「缺少 RELEASES_TOKEN」或 401 时，让 Jeremy 重新生成令牌并替换这个密钥。**不要把令牌写到任何地方。**

**其他 CI 说明**
- `pinyin-check.yml`：在 Linux 上编译并测试拼音引擎，改了拼音词库或引擎后手动跑。
- 本地服务端测试：`python -B -m unittest discover -s bridge -p 'test_*.py' -v`
- 旧方法：电脑上 `发布实验包.ps1 -RunId <编号>`，效果一样。

## 5. 运行环境（识别服务）

### 家里电脑桥接（现在在用）
- 项目根目录：`C:\Users\YaoHa\CodexShare\CapsWriter-iOS-ZeroFee-20261105`
- 电脑上运行的桥接代码在 `branches\phone-asr\bridge`（这是 `feature/phone-asr` 的本地工作树）。改了 `bridge/` 后，要在这个工作树拉取最新代码再重启桥接。
- 启动：双击 `后台启动语音桥接.cmd`；停止：`停止语音桥接.cmd`；查看状态：`查看语音桥接状态.cmd`。日志在 `private\logs\`（失败看 `bridge-error.log` 最后几行）。
- **桥接不会自动重启**：电脑重启后它不会自己起来，手机会看到 502 错误。解决办法：双击 `后台启动语音桥接.cmd`。（可以考虑做成开机自启，见待办。）
- 识别引擎是用户自己装的开源 CapsWriter-Offline（Qwen3-ASR），本仓库不含它的源码和模型。边说边上屏的草稿模型（sherpa-onnx）在 `private\stream-model\`，启动参数 `--stream-model` 已写进 `bridge-background.ps1`。
- 外网访问：Tailscale Serve，`/v1` 转发到桥接端口 **8765**（8080 是一个笔记页面，与桥接无关）。

### AWS GPU 备用服务器（暂停中）
- 目标：家里电脑关机时，手机也能通过 AWS 识别；停录到上屏 ≤ 3 秒。CPU 太慢（约 16–22 秒），需要 GPU（g4dn.xlarge，T4，Ohio us-east-2）。
- 2026-11-09 暂停在开机前：配额 4 vCPU 已批、已升级付费套餐、预算提醒每月 30 美元，**还没有创建任何实例**。AWS 赠金当时约 80 美元、约 50 天后（2026 年 12 月底前后）到期。
- 接续步骤在 Claude 项目文件 `aws-gpu/接续步骤.md`（建议 Jeremy 复制一份到本地）。服务端 GPU 代码在分支 `claude/project-thread-tsvf8p`（GPU 开关、从压缩包装 GPU 库、30 分钟空闲自动关机），**还没开 PR**。部署文档：[CLOUD.zh-CN.md](CLOUD.zh-CN.md)。
- App 里已有家里电脑 / AWS 手动切换（`ios/Shared/BridgePairing.swift`）。
- 原则：AWS 控制台由 Jeremy 手动操作；任何开机前都要先设好自动停机兜底，不要让实例一直开着烧钱。

- 2026-11-22 决定：代码仓库转私有，安装包改放公开的 `saykey-releases`（PR #23 已完成）。
