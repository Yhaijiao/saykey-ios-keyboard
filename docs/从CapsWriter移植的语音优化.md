## P0-1 去语气词

规则（在本地用规则做，不调用大模型，零延迟）：

| 类别 | 词 | 去掉的条件 |
|---|---|---|
| 任何位置都去 | 呃、嗯 | 出现就删 |
| 只在单独成段时去 | 额、啊 | 前面是句首或标点，后面是逗号、顿号或句尾时才删。**否则「额度」「好啊」会被误伤** |
| 英文 | um、uh、uhm、erm | 整词匹配才删 |

删完以后要收拾标点：连着的逗号合成一个，句首不留标点，句尾不留逗号。

## P0-2 去口吃重复

原则：**宁可少改，也不乱改。** 拿不准的叠词（看看、检查检查、一个一个）保持原样。任何一步出错或结果为空，就返回原文。

| 情况 | 处理 | 例子 |
|---|---|---|
| 常见单字连说 | 只留 1 个。限这些字：我你他她它这那不就的也都还把给跟再没但挺很 | 我我我觉得 → 我觉得 |
| 单字前面是固定词 | 不动 | 其他他们、目的的、成都都、一把把 |
| 任意单字连说 3 遍以上 | 只留 1 个 | 我想想想 → 我想 |
| 本身就是叠字的词 | 压成 2 个。限这些字：仅刚常渐稍偏恰悄默 | 仅仅仅仅 → 仅仅 |
| 连说 3 遍是正常语气 | 不动。限这些字：对好行是哈嘿呵嘻嗯啊哦噢喔来走快慢谁叉点某等 | 对对对、哈哈哈 |
| 正反问句前面多出来的字 | 删掉多余的。只多 1 个字时，要在句首或标点后才删 | 是是是不是 → 是不是。但「功能能不能」「需要要不要」不动 |
| 隔着逗号重复的口头禅 | 只留 1 个。限这些词：就是、这个、那个、然后、所以、因为、但是、如果、还有、比如、比如说、我们、你们、他们、我说、我想、我觉得、就是说 | 就是，就是 → 就是 |
| 2–8 字的词连着重复（ABAB） | 只留 1 遍 | 这个这个 → 这个 |
| 重复两遍本身就是正常说法 | 白名单，不动 | 检查检查、讨论讨论、确认确认、谢谢、慢慢、什么什么……（约 60 个） |
| 3–10 字的片段隔着逗号重复 | 只留 1 遍，**含数字的不动** | |
| 英文单词重复 | 只留 1 个。白名单不动：very、so、no、yeah、really、bye 等 | the the plan → the plan；I I think → I think |

## P2 请顺便检查 SayKey 有没有这些问题

### 1. 越用越慢（11-23 查出来的）
- **现象**：每句话识别要等的时间越来越长，「愈演愈烈」。
- **原因**：同一块显卡（RTX 4070，12 GB）上同时放着识别模型和润色模型（Ollama qwen3.5:4b，设成闲置 1 小时才卸载）。显存满了以后，Windows 把识别模型的一部分挪到普通内存，每个字的生成时间从约 0.01 秒变成 0.16–0.26 秒，慢了十几倍。
- **修法**：润色模型闲置 10 分钟就卸载（Ollama 的 `keep_alive='10m'`）。
- **对 SayKey 的意义**：SayKey 的识别服务原来也跑在这台电脑的 8080 端口。如果它也用这块显卡，或者和 Ollama 共用，同样会出这个问题。建议：
  - 每句记一行分步耗时日志（编码 / 读入 / 逐字生成 + 生成了几个字），平均每个字超过 0.05 秒就报警。
  - 润色模型不要长时间常驻显卡。

### 2. 截图被识别结果覆盖（11-24）
- **现象**：先截图，再说话，识别结果自动放进剪贴板，截图就没了。
- **修法**：剪贴板里是用户自己复制的东西（图片、文件、文字）时，不往剪贴板写识别结果，并提示一句「剪贴板里有……，没覆盖」；只有剪贴板为空、或里面是上一句识别结果时才覆盖。要是必须借剪贴板粘贴，就先把图片原样存下来，粘贴完再放回去。
- **对 SayKey 的意义**：iOS 键盘一般是直接插入文字，不碰剪贴板，多半没有这个问题。如果 SayKey 有「结果自动复制」之类的功能，要照这个处理。

### 3. 润色改错
- 大模型润色有时会改错，比如把「+1」写成了「加号一」。
- 建议：先用上面的本地规则处理语气词和重复字，大模型润色只管断句和标点。每句同时记下原文、规则处理后、大模型润色后三版，出错时能分清是哪一步改坏的。
